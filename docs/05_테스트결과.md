### 2.1 계산·저장 검사에서 확인한 것

- 원본 개수·ID 보존, 중복 ID·연결 오류·순매출 불일치·잘못된 날짜 거부.
- 판매량×단가−전체 할인, 전체 수수료 한 번 차감, 날짜별 가격·채널별 포장 원가, 과거 원가 보존.
- 공헌이익·합계 기준 이익률, 무료 판매의 비율 계산 불가, 음수 이익, 소수 정밀도와 최종 반올림.
- 수수료 공란·수량 0/음수/소수·할인 초과·미래 날짜·과대 금액·판매 중복 거부, 명시적 수수료 0 허용.
- 일별 비용만 사용, 월계획·입고 대금 이중 차감 방지, 비용만 있는 날과 마감·미마감·자료 없음 구별.
- 초기재고·입고·폐기·포장재·판매 사용량, 기준일 이후 기록 제외, 실측 이후 움직임, 과거 판매 변경 시 실측값 보존.
- 최초 초기화 경합, 재실행·저장 보존, 변경번호 충돌 차단, 저장 실패 시 이전 상태 유지, 손상 자료 자동 덮어쓰기 방지, 유효한 빈 기록 상태 유지.
- 1 미만의 음수 재고 부호와 매우 큰 합계의 표시 정밀도.

B01에서 브라우저 콘솔 오류·실행 오류는 0건, 관찰된 외부 주소 요청은 0건이었다. 프로그램에는 기록 전송 API가 없다. 이 결과는 검사한 흐름의 근거이며 모든 운영 환경의 보안 보장을 뜻하지 않는다.

성능은 로컬 검사에서 처음 자료 표시 **1,539ms**, 판매 저장부터 결과 표시 **198ms**였다. 테스트 전용 PC·브라우저에서 한 번 측정한 값이며 모든 환경에서의 보장은 아니다. 파일 처리 성능과 운영 배포 검사는 해당 EPIC·최종 배포 때 수행한다.

### 2.3 검사 중 수정한 사항과 한계

- 선택칸을 정확한 이름으로 식별하도록 이름 연결을 보완했다.
- 브라우저 검사의 임의 예상 원가를 원본 가격이력과 대조해 수정했다. 실제 원두는 24.84원/g, 컵세트는 166.4원/개다. 프로그램 계산 기준을 바꾼 것이 아니다.
- 누락된 브라우저 아이콘 요청으로 생기던 404를 제거했다.
- 표시에서 일반 소수로 변환하지 않고 정밀 숫자를 유지하며, 1 미만 음수 재고의 부호도 검사했다.
- 대시보드의 접힌 목록이 미기록 날짜만 보여 주던 문제를 수정했다. 기록 있는 날짜를 먼저 표시하고 전체 펼침에서 미기록 날짜도 확인한다. 합계는 바뀌지 않는다.
- 대시보드의 재고 기준일을 조회 날짜/조회 월의 마지막 실제 기록일과 연결했다. 날짜와 마감 기준은 화면에 별도로 표시한다.
- 검사 도구의 알려진 취약점은 Vitest 업데이트로 수정했고 이후 관련 검사를 재실행했다.
- 빌드에 Zod 소스 주석의 최적화 표시를 제거했다는 경고가 남는다. 빌드·실행 오류는 없으며 의존 패키지 내부 주석을 임의 수정하지 않았다.
- `design/_3/screen.png`는 손상된 파일이어서 판매 입력은 해당 HTML과 FRD로 구현했다. 사용자 화면 확인이 필요하다.

**사용자 확인 완료 6/6, Story 최종 완료 5/5, EPIC 완료 1/1.** U01~U03의 개별 응답과 나머지 항목에 대한 사용자 “모두 확인했고 다음 EPIC으로 넘어가자”를 근거로 완료 처리했다. 개별 추가 관찰을 에이전트가 대신 수행했다고 기록하지 않는다.

이전 확인 이력: 2026-10-12 동일 작업 요청을 다시 받아 개발계획과 당시 브라우저를 확인했다. 프로그램은 열려 있으며 메뉴 8개·재료 11개·판매 6,112건으로 표시된다. 이는 에이전트의 화면 재확인이며 사용자 U01 합격 응답은 아니다. EPIC 1 사용자 확인을 이어가며 EPIC 2는 시작하지 않았다.

### 7.4 성능·보호·오류 대응

측정 환경은 현재 Windows PC, 임시 브라우저 프로필, 로컬 주소다. 일반 인터넷이나 Vercel 운영 주소의 성능 측정으로 대신하지 않는다.

- 엑셀 10MiB·데이터 20,000행·200,000셀·실제 압축 해제 64MiB, JSON 백업 50MiB 한도. 한도 초과는 일부 반영 없이 중단한다.
- 무거운 파일 생성·검사·복원 검사는 별도 처리 도구(Web Worker)에서 실행한다. 최대 30초와 취소를 제공하고 연속 확정을 막는다. 파일 도구는 해당 화면에서 필요할 때 불러온다.
- 기록과 파일은 브라우저 안에서 처리한다. 검증한 배포 파일 흐름의 외부 요청·콘솔 오류·보안 정책 위반은 Chrome·Edge 모두 0건이다. 로그인·서버 저장·통계 전송은 추가하지 않았다.
- 손상·형식/버전 오류를 알리고 저장 실패를 성공으로 표시하지 않는다. 예기치 않은 화면 오류에는 기록 초기화 없이 다시 여는 안내를 제공한다.
- `vercel.json`의 코드 실행 출처 제한·프레임 차단·콘텐츠 형식 보호·참조 주소 비공개 설정을 실제 배포 파일을 제공하는 검사 서버에 적용해 확인했다. **Vercel 운영 응답에 적용되었는지는 실제 배포 후 별도 확인해야 한다.**

### 7.5 발견·수정과 남은 작업

- 최초 파일 도구를 여는 개발 환경에서 라이브러리 사전 준비가 페이지 재시작을 일으키던 부분을 Vite 설정으로 보완하고 재검사했다.
- 복원 후 이전 입고 저장 알림이 함께 남던 부분을 수정했다. 최종 전체 검사에서는 같은 문제가 재현되지 않았다.
- 검사 코드에서 임시 다운로드 경로의 확장자가 없는 점, 화면 재진입 시 기록 종류 재선택, 조회 날짜 확정 대기와 빈 메뉴 표의 확인 방법을 실제 사용자 동작에 맞게 고쳤다. 검사를 약하게 하거나 실패를 숨겨 완료하지 않았다.
- 전체 **14/14 Story, 3/3 EPIC 개발·검수 완료**. 사용자 직접 확인은 EPIC 1의 5개 Story이며, EPIC 2·3의 9개 Story는 명시적 위임 검수다.
- **GitHub 업로드·Vercel 실제 배포·고정 운영 주소 재실행 검사는 아직 수행하지 않았다.** 배포 후 주소별 저장소 분리와 실제 응답 보안 설정을 확인해야 한다. 이 문서의 로컬 검수 완료를 운영 배포 완료로 표시하지 않는다.
- 주/분기/반기/연간 조회, 예상 손익·발주량 등 2차 범위는 추가하지 않았다. 전체 기획부터 배포까지 실제 4시간 준수 여부는 측정 기록이 없으므로 달성했다고 표시하지 않는다.
