# 카페 운영 기록 웹 프로그램 기능 요구사항 문서(FRD)

- 작성일: 2026-10-12
- 기준 문서: [01_PRD.md](01_PRD.md)
- 상태: FRD 작성 완료. 프로그램 구현·검사 완료를 뜻하지 않는다.
- 합의: 사용자가 PRD 우선 적용 추천안을 선택하고 문서 완성을 요청했다. 이 문서는 기존 PRD의 업무 원칙을 유지하며 그 안에서 필요한 상세 처리와 계산 방법을 추천안으로 구체화한다. 시안에만 있는 새 기능을 승인받은 것으로 처리하지 않는다.
- FRD는 기능 요구사항 문서다. 사용자의 입력, 프로그램의 처리, 화면·저장 기록·파일의 결과와 실패 시 동작을 설명한다. 개발 언어·저장 기술·배포 구성은 정하지 않는다.

## 1. 프로그램과 범위

한 매장의 운영자 한 명이 같은 PC의 브라우저에서 판매·비용·재고를 관리한다. 판매를 저장하면 메뉴 수익성, 기간 손익, 레시피에 따른 재료 잔량이 함께 바뀐다. 자료는 원·부가세 제외, 재료는 g·ml·개 기준이다.

**1차:** 제공 샘플 시작, 판매·비용 입력/수정/삭제, 메뉴 수익성, 일·월 손익, 입고·폐기·실제 재고 기록과 잔량, 판매·비용 엑셀 양식/가져오기, 저장·백업·복원.

**2차:** 예상 손익, 발주 참고량, 주·분기·반기·연간 조회, 메뉴·재료·레시피·가격이력 관리, 재고 엑셀 가져오기, 상세 비교·수익성 분류. 2차 기능은 여기서 처리 방향과 계산 후보를 제안하되 1차에 넣지 않는다.

**보류:** 실적 리포트 엑셀 내보내기, 감사 로그, 원가 변동 시뮬레이션, 목표 관리, 발주 등록·자동 주문, 정기 실사 알림. 시안에 존재해도 PRD 필수 기능으로 확정되지 않았다. 추가하려면 별도 확인이 필요하다.

## 4. 공통 처리 원칙

### 4.1 기록과 상태

- 판매 한 행은 **하루·메뉴·채널 하나의 합계**다. 같은 날짜·메뉴·채널을 새로 입력하면 기존 기록 수정을 안내한다. 판매량을 더하는 별도 주문 입력 기능을 만들지 않는다.
- 각 기록에는 고유 식별번호가 있다. 수정은 같은 번호를 유지한다. 새 비용은 같은 날·같은 항목이어도 별도 지출일 수 있으므로 금액이 같다는 이유만으로 자동 합치지 않는다.
- 미입력, 해당 없음, 숫자 0, 계산 불가를 구별한다. 필요한 가격·레시피·초기재고가 없으면 해당 결과는 ‘계산 불가: 필요한 자료’로 표시한다. 일부 계산 불가 자료가 있으면 전체 결과를 정상 합계인 것처럼 표시하지 않는다.
- 저장 전 화면 미리보기는 ‘입력 중’이며 확정 실적이 아니다. 한 변경은 기록과 연관 결과를 함께 반영한다. 하나라도 실패하면 기존 저장 상태를 유지한다.
- 조회·미리보기·취소는 저장 기록을 바꾸지 않는다. 일반 기능은 원본 `data` 파일에 덮어쓰지 않는다.
- 성공 알림은 저장 또는 파일 생성이 실제로 끝난 뒤 표시한다. 실패하면 원인·재시도 방법을 알리고 입력 중 값을 유지한다.

### 4.2 날짜와 마감

- 조회 대상 기간과 기록 기준일을 함께 표시한다. 처음에는 샘플 마감 기준일 2026-09-18이 포함된 달을 보여 주는 방식을 추천한다. PC의 오늘 날짜로 샘플 기준일을 바꾸지 않는다.
- 일은 해당 날짜, 월은 해당 월 첫날부터 마지막 날까지다. 매출·비용 합계와 재고의 기준일을 구별한다. 재고는 기간 합계가 아니라 기준일 끝의 잔량이다.
- 원본 `record_complete`를 마감 상태로 사용한다. 저장한다고 자동으로 마감하지 않는다. 마감 후 기록을 고치면 해당 날짜는 ‘수정 후 확인 필요’로 구별한다.
- 새 날짜·미마감 날짜의 입력은 허용하되 ‘입력된 참고 실적’으로 보여 주고 기존 마감 실적과 구별한다. 미마감·자료 미포함 날짜를 매출 0인 마감일로 합산하지 않는다.
- 마감 처리 버튼·절차는 PRD·시안에 정의되어 있지 않다. 새로운 마감 관리 기능은 추가하지 않는다. 새 기록을 확정 마감으로 전환하는 기능이 필요하면 별도 확인한다.
- 미래 예정 판매·입고를 실적으로 기록하는 기능은 1차에 없다. PC의 오늘 이후 날짜의 실적 입력은 오류로 안내한다. 조회 자체는 가능하며 자료 없음으로 표시한다.

### 4.3 입력·실패·동시 조작

- 날짜는 실제 존재하는 날짜, 수량·금액은 숫자인지 검사한다. 문자·무한대·잘못된 날짜는 저장하지 않는다. 천 단위 쉼표는 입력 편의를 위한 표시로 취급한다.
- 판매량은 양의 정수, 가격·할인·수수료는 0 이상의 금액이다. 비용은 양의 금액이다. 입고·폐기는 양의 수량을 입력하고 프로그램이 증감 방향을 적용한다. 실측 수량은 0 이상이다. ‘개’는 정수, g·ml는 소수 입력을 허용한다.
- 판매량 0은 삭제로 처리하도록 안내한다. 무료 판매는 단가 0 또는 전액 할인으로 기록할 수 있으나 공헌이익률은 계산 불가일 수 있다. 반품·환불·음수 판매/비용은 1차 범위가 아니며 음수 기록으로 우회하지 않는다.
- 필수값 오류는 위치와 이유를 표시한다. 저장을 반복 클릭해도 동일 기록이 두 번 생기지 않도록 한다. 처리 중 중복 실행을 막는다.
- 수정 중 취소·닫기·화면 이동은 입력 폐기 확인 후 종료하는 방식을 추천한다. 실패·취소 시 확정 기록을 바꾸지 않는다.
- 다른 탭 등에서 원본이 변경된 경우 기존 화면의 값으로 덮어쓰지 않고 다시 읽기를 안내한다. 여러 사용자 동시 작업 기능은 추가하지 않는다.

## 5. 1차 기능 상세

표의 ‘파일’은 사용자에게 내려받는 파일이다. ‘저장 기록’은 재실행 후에도 사용할 프로그램 자료를 뜻한다. 파일 없음은 백업에 해당 기록을 포함하지 않는다는 뜻이 아니다.

### F01. 제공 자료로 시작 — M01

| 구분 | 요구사항 |
| --- | --- |
| 시작 | 처음 사용할 때 기존 저장 자료 유무를 확인한다. |
| 처리 | 저장 자료가 없으면 제공 엑셀 또는 JSON 중 하나를 기준으로 공급사·재료·메뉴·레시피·가격·달력·초기재고·판매·재고·비용·월계획·자료정보를 한 번 불러온다. 일반 JSON 자료 가져오기 기능으로 확장하지 않는다. |
| 화면·기록·파일 | 가상 샘플임과 기록 기간을 알린다. 메뉴 8개, 재료 11개, 판매 6,112건, 비용 3,560건, 재고 1,515건을 시작 자료로 유지한다. 저장된 기록이 있으면 이어서 연다. 내려받는 파일은 없다. |
| 예외 | 파일 누락·손상·중복 ID·알 수 없는 연결 대상이면 원인과 대상을 안내하고 불완전한 자료를 정상 상태로 저장하지 않는다. 기존 기록이 읽히지 않아도 샘플로 자동 덮어쓰지 않는다. |

### F02. 판매 목록·조회 — M02

| 구분 | 요구사항 |
| --- | --- |
| 사용자 행동 | ‘판매 및 비용 기록’ → ‘판매 기록’, 조회 날짜 또는 월 선택. |
| 처리 | 해당 기간의 판매를 불러온다. 메뉴·채널·기간은 원본 기록에 따라 구분한다. |
| 화면 | 날짜, 메뉴, 채널, 수량, 당시 단가, 행 전체 할인액, 순매출, 행 전체 수수료, 식재료/포장 원가, 수정·삭제 조작과 합계를 표시한다. 거래 시각은 표시하지 않는다. 합계는 C01~C04를 따른다. |
| 기록·파일 | 조회는 기록을 바꾸지 않고 파일을 만들지 않는다. |
| 예외 | 자료가 없으면 빈 목록과 자료 없음 안내. 마감된 무판매일은 0, 미마감일은 미마감으로 구별. 자료 읽기 실패는 조회 실패로 안내하며 0원 실적으로 바꾸지 않는다. |

### F03. 판매 추가·미리보기 — M02

| 구분 | 요구사항 |
| --- | --- |

## 6. 계산 방법

다음은 PRD의 비용 범위를 지키는 상세 계산 추천안이다. 원본의 과거 결과와 새로 계산한 결과의 출처를 구별한다. 계산 결과를 원본 파일에 덮어쓰지 않는다.

### C01. 순매출·수수료

- 판매 총액 = 판매수량 × 당시 실제 판매단가.
- 행 순매출 = 판매 총액 − 행 전체 할인액.
- 결제수수료는 해당 행에 기록하거나 입력한 **전체 금액**이다. 1개당 금액으로 다시 곱하지 않는다. 수수료율을 자동 2.5%로 고정하지 않는다.
- 과거 파일의 순매출은 보존하며 수량·단가·할인과 일치하는지 검사한다. 맞지 않으면 조용히 고치지 않고 해당 기록의 불일치를 알린다.
- 예: 5,000원 메뉴 10개, 전체 할인 2,000원, 수수료 1,200원이면 순매출 48,000원이다.

### C02. 재료·포장 원가

- 기준단위당 재료가격 = 적용 구매가격 ÷ 적용 구매용량. 적용일은 판매일 이하인 가격이력 중 가장 최근 날짜다.
- 메뉴 한 개 식재료원가 = 적용 레시피의 식재료별 사용량 × 해당 재료의 기준단위 가격을 모두 더한 값.
- 포장원가는 같은 방식으로 해당 채널에 적용되는 포장 재료만 합산한다. 원본 I10 포장컵세트, I11 디저트포장세트는 포장원가로 구별한다. 적용채널 공란은 모든 채널, ‘포장’은 포장 판매만 해당한다.
- 행 식재료/포장원가 = 각각의 저장된 개당 원가 × 판매수량. 과거 판매는 원본에 보관된 개당 원가를 사용한다.
- 예: 원두 1,000g 가격 23,000원, 한 잔 사용량 20g이면 원두 원가 460원이다. 매장 판매에서 포장 전용 재료는 제외한다.
- 필요한 날짜의 가격이나 레시피가 없거나 구매용량이 0이면 계산 불가다. 오래된 최초가격이나 현재가격으로 임의 대체하지 않는다. 단위 g·ml 간 변환을 밀도 근거 없이 하지 않는다.

### C03. 메뉴 직접 공헌이익

- 행 직접비 = 행 식재료원가 + 행 포장원가 + 행 결제수수료.
- 행 공헌이익 = 순매출 − 직접비. ‘공헌이익’은 임차료·인건비 등을 내기 전에 메뉴가 남기는 금액이다.
- 기간·메뉴·채널 합계는 해당 행들을 더한다. 1개당 평균 공헌이익 = 총 공헌이익 ÷ 총 판매수량.
- 이익률 = 총 공헌이익 ÷ 총 순매출 × 100. 행별 이익률의 단순 평균을 사용하지 않는다. 분모가 0이면 ‘계산 불가’를 표시한다.
- 예: 순매출 48,000원, 식재료비 10,000원, 포장비 1,000원, 수수료 1,200원이면 공헌이익 35,800원, 이익률 약 74.6%다. 메뉴 순이익이라고 부르지 않는다.

### C04. 기간 손익·비용

- 기간 순매출/직접비 = 같은 기간의 해당 판매 행 합계.
- 기간 기타 비용 = 같은 기간에 귀속된 비용기록 금액 합계. 월비용계획은 합산하지 않으며 비용을 또 나누지 않는다.
- 운영 참고 손익 = 기간 순매출 − 기간 직접비 − 기간 기타 비용.
- 운영 손익률 = 운영 참고 손익 ÷ 기간 순매출 × 100. 순매출 0이면 계산 불가다.
- 예: 순매출 100만원, 직접비 30만원, 일별 비용 40만원이면 손익 30만원이다. 월계획에 같은 40만원이 있어도 다시 차감하지 않는다.
- 입고 대금은 재료를 산 현금 지출과 판매에 사용한 원가의 차이 때문에 다시 비용 합산하지 않는다. 1차 손익은 폐기 평가손실·실사 차이 평가액·세금 등을 별도 계산하지 않는 운영 참고 값이다.
- 마감 실적과 미마감 입력 합계는 구별한다. 월 요약에는 실제 포함한 날짜 범위를 표시한다. 마감된 무판매일에 비용이 있으면 비용을 빠뜨리지 않는다.

### C05. 재료 잔량·부족

- 판매 사용량 = 해당 재료가 적용되는 레시피의 한 개 사용량 × 판매수량을 기간 내 모두 더한 값. 식재료와 포장 재료 모두 해당한다.
- 실사가 없으면 기준일 잔량 = 초기재고 + 초기 기준일부터 해당일까지 입고량 − 폐기량 − 판매 사용량 + 실측값 없는 수량조정.
- 초기재고는 첫날 영업 시작 전 값이다. 첫날의 판매·입고·폐기도 이후 움직임에 포함한다. 조정 수량은 원본 부호를 유지한다.
- 예: 초기 원두 6,000g, 입고 1,000g, 폐기 100g, 판매 사용 2,000g이면 4,900g이다.
- 잔량 0 이하는 부족/확인 대상이며 음수를 0으로 바꾸지 않는다. 양수는 충분함을 보장하지 않는다. 단위가 다른 재료 수량을 합쳐 총 g·ml처럼 표시하지 않는다.

### C06. 실사와 과거 수정

- 같은 날짜의 순서는 초기재고 → 입고·폐기·판매·실측 없는 조정 → 마감 실사로 보는 방식을 추천한다. 자료에 시각이 없어 시간 단위 선후를 만들어낼 수 없다.
- 실사 당시 차이 = 실제 센 수량 − 그 실사 직전의 계산 잔량. 이 차이는 ‘그때 확인한 차이’로 보관한다.
- 실사 이후 조회 잔량 = 가장 최근 실사 수량 + **그 실사일 다음 날부터** 조회 기준일까지의 입고 − 폐기 − 판매 사용량 + 실측값 없는 수량조정.
- 실사 수량을 기준으로 삼은 경우 그 실사의 기존 증감수량을 다시 더하지 않는다. 원본 실사 이벤트의 `counted_quantity`가 실제 수량, `quantity`가 당시 차이다.
- 예: 장부 2,450g, 실측 2,100g이면 당시 차이 −350g이다. 다음 날 입고 1,000g, 판매 사용 500g이면 잔량 2,600g이다.
- 실사 이전 판매를 고쳐도 해당 실측 2,100g을 바꾸지 않는다. 과거 판매일 손익과 실사 이전 계산 잔량은 바뀔 수 있다. 당시 보관한 차이를 현재 재계산 결과와 같은 의미로 덮어쓰지 않는다.
- 실사 후 판매 수정은 다음 실사 전까지의 잔량에 영향을 준다. 이후 실사가 있으면 그 시점의 실측값이 다시 기준이 된다. 과거 날짜에 새 실사를 넣어도 이후 실측 수량 자체는 유지한다.

### C07. 정밀도·반올림

- 직접 입력하는 원화 금액은 정수 원을 추천한다. 원본 개당 원가·단위당 가격의 소수는 보존한다. 원가 계산 중간 단계는 반올림하지 않는다.
- 원화 합계는 원본 정밀도로 합한 뒤 표시할 때 원 단위로 반올림한다. 음수는 절댓값에 같은 반올림을 적용하고 부호를 복원한다. 비율은 합계로 구한 뒤 소수 첫째 자리까지 표시한다.
- 재료 g·ml는 최대 소수 셋째 자리 입력을 추천하며 ‘개’는 정수다. 내부 잔량 판단은 표시 반올림 전 값을 사용한다. 0이 아닌 작은 값이 0으로 보이지 않도록 ‘0 초과 0.001 미만’처럼 표시한다.
- 표의 반올림된 행을 더한 값과 총합 표시가 다를 수 있음을 설명한다. 백업에는 표시값 대신 원래 정밀도의 기록을 보관한다.

## 8. 2차 기능의 처리·계산 제안

다음은 PRD에 이미 포함된 확장 기능이다. 1차 범위가 아니며, 아래 계산 후보는 2차 착수 시 확인할 **미정 제안**이다. 1차 필수 기능과 섞어 구현하지 않는다.

| 기능 | 사용자 행동 → 처리 → 화면·파일 결과 | 계산 후보와 오류·예외 |
| --- | --- | --- |
| X01 예상 월말 손익 | 조회 월 선택 → 마감된 실적·남은 영업일·계획 비용 구별 → 실적과 예상 손익·기준일·가정을 따로 표시. 별도 파일 없음 | 최근 마감 영업일의 일평균 순매출·직접비로 남은 영업일을 예상하고, 월계획의 잔여 비용은 이미 반영한 실적 비용과 중복되지 않게 추정하는 안. 평균 기간과 계획 초과 처리 미정. 마감 영업일 없음·자료 부족이면 계산 불가. 미래를 실적 0으로 채우지 않음 |
| X02 부족 예상·발주 참고량 | 재료/기준일 확인 → 소비 추세·납기·안전일수·구매용량 고려 → 필요량과 구매 포장 수, 근거를 참고용으로 표시. 주문 파일·자동 주문 없음 | 후보: 일평균 판매 사용량 × (납기 영업일+안전 영업일) − 잔량, 0 미만은 0; 구매 포장 수는 구매용량 단위로 올림. 평균 기간·입고 예정량 처리 미정. 음수 잔량은 우선 실사 안내, 소비 자료 없음·영업달력 범위 부족·구매용량 0이면 추천 불가 |
| X03 기간 조회 확장 | 주/분기/반기/연 선택 → 일별 기록을 경계에 맞춰 집계 → 같은 손익 항목과 포함 날짜 표시. 파일 없음 | 주는 월~일, 분기는 1~3/4~6/7~9/10~12월, 반기는 1~6/7~12월, 연간은 1~12월. 수익률은 합계 기준, 재고는 기간 마지막 유효 기준일 잔량. 일부 자료만 있으면 부분 기간 표시 |
| X04 기준 자료 관리 | 메뉴·재료·레시피·가격이력 관리 → 연결·적용일 검사 → 신규 기록에 적용, 과거 당시 원가는 보존 | 구체 입력·편집·삭제 제한과 적용일 겹침 처리 미정. 참조 중인 자료 삭제로 기존 계산이 깨지지 않게 해야 함. 별도 내보내기 추가 없음 |
| X05 재고 엑셀 가져오기 | 재고 양식 작성·선택 → 이벤트/단위/실사 관계 검사 → 기록과 잔량 갱신 | 파일 구성·중복/오류 정책은 2차 확정. 입고·폐기 부호와 실제 수량을 혼동하거나 기존 실사와 충돌하면 반영하지 않음 |
| X06 상세 비교·수익성 분류 | 기간/메뉴 선택 → 확정 기준으로 비교·분류 → 근거와 대상 표시 | 등급 경계·최고/최저 순위 기준 미정. 시안 65%/55%는 채택하지 않음. 매출 0·자료 누락은 임의 등급 부여 금지 |

## 10. 확정 범위와 남은 사항

사용자의 이번 선택으로 **PRD 우선, 1차·2차 유지, 시안 신규 기능 보류**를 확정했다. 1차 기능의 계산·오류·저장·파일 처리에는 이 문서의 추천 상세안을 적용한다. 원본 자료에서 관찰한 사실과 제품 처리 추천안을 구별해 작성했다.

2차의 전망 평균 기간·발주 판단 기준·수익성 등급, 보류 기능 추가 여부, 새 기록의 별도 마감 관리, 재고 이벤트 수정·삭제 기능 추가 여부는 확정하지 않았다. 1차에 몰래 포함하지 않는다. 실제 저장·파일 처리 기술과 화면 구성의 보완은 후속 설계에서 정한다. 손상된 판매 화면 이미지는 HTML로 기능을 확인했으며 시각 설계 검토 시 정상 시안 확인이 필요하다.
