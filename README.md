# 프렙 카페 운영 기록

현재 구현 범위는 **EPIC 1~3 / S01~S14**입니다. 판매·비용 관리, 메뉴 수익성·일/월 손익·재료 잔량, 입고·폐기·실사, 엑셀 가져오기, 전체 백업·복원을 제공합니다. EPIC 1은 사용자 직접 확인, EPIC 2·3은 사용자가 위임한 검수 결과를 [테스트결과](docs/05_테스트결과.md)에 구분해 기록합니다.

## 실행

Node 22.x(22.12 이상)에서 `npm ci` 후 `npm run dev`를 실행하고 http://127.0.0.1:5173 을 엽니다. 설치된 프로젝트에는 Node 22 실행 도구도 포함되어 npm 스크립트가 해당 버전을 사용합니다. 설치 스크립트 실행을 차단하는 npm 환경에서는 잠금 파일에 지정한 Node·esbuild 설치 스크립트만 허용해야 합니다.

같은 주소·같은 브라우저 프로필에 IndexedDB로 기록을 저장합니다. 주소·포트·프로필이 바뀌면 별도 저장소입니다. `data`는 제공받은 가상 샘플 원본이며 `public/sample.json`은 동일 자료의 배포용 사본입니다. 입력한 기록을 이 파일이나 외부 서버에 기록하지 않습니다. 환경을 옮길 때는 기존 주소에서 백업 파일을 내려받아 새 주소에서 복원하세요.

`백업 및 데이터 관리`에서 판매/비용을 선택해 전용 `.xlsx` 양식을 내려받습니다. 오류 행이 있으면 전체 반영을 차단하며 검사 후 확정해야 저장됩니다. 기존 기록의 수정은 목록에서 합니다. 엑셀은 10MiB·데이터 20,000행·200,000셀·압축 해제 64MiB까지, 백업은 50MiB까지 지원합니다. 파일 처리는 30초 제한과 취소를 제공합니다. 복원은 미저장 입력을 폐기하고 현재 자료 전체를 교체하므로 먼저 현재 백업을 보관하세요.

## 검사

- `npm test`: 계산·입력·저장 검사
- `npm run test:e2e`: 실행 중인 로컬 서버를 대상으로 테스트 전용 Edge 브라우저에서 실제 IndexedDB·화면 흐름 검사
- `npm run build`: TypeScript 검사 및 배포용 정적 파일 생성
- `npm run test:production`: `dist`와 Vercel용 보안 설정으로 Edge에서 실제 다운로드·가져오기·백업·복원을 3회 검사. PowerShell에서 `$env:PRODUCTION_BROWSER='chrome'`을 설정하면 Chrome으로 검사합니다. 검사 서버는 임시 포트를 사용하고 종료됩니다.

브라우저 자동 검사는 별도 임시 프로필을 사용하므로 사용자 확인용 브라우저 기록을 바꾸지 않습니다. `vercel.json`에는 배포 파일 위치와 보안 응답 설정이 있습니다. 코드·문서·검사 결과는 [GitHub 저장소](https://github.com/itconnect-ai/planning_test)의 `main`에 보관했습니다. 실제 Vercel 배포와 고정 운영 주소 검사는 아직 수행하지 않았습니다.
